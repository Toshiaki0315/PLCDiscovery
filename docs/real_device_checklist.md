# 実機確認チェックリスト

シミュレーターでの確認だけでは分からない点（機種ごとの応答の違い、1 回に読める点数の上限、アドレスの数え方など）を、実機で確かめるための手順です。

> **安全のために**
> - 本ツールは読み取り専用です。書き込みは一切行いません。
> - それでも、最初は**工場停止中**か、**検証用の PLC** で実施してください。
> - 生産中の PLC では、範囲指定モード・小さな範囲・既定のパケット間隔（50 ms）から始めてください。

## 0. 準備

- 対象 PLC の IP アドレス、ポート、プロトコル設定（SLMP のフレーム・交信データコード、EtherNet/IP のスロットなど）を控えておく
- PLC 側の設定ツール（GX Works、KV STUDIO、Sysmac Studio、TIA Portal、Studio 5000 など）で、確認するアドレスの**現在値**を表示できるようにしておく
- 結果を残すフォルダを決める（例：`-o ./実機確認_YYYYMMDD`）

## 1. 共通の確認（全メーカー）

| # | 確認内容 | コマンド例 | 期待する結果 |
|---|---|---|---|
| 1-1 | 探索で見つかる | `python plc_scanner.py --mode discover --ip-range <IP>/32` | メーカー・機種・プロトコルが正しく表示される |
| 1-2 | 値が設定ツールと一致する | `--mode range --target <IP> --protocol <p> --device <D> --range 0-9` | CSV の値が設定ツールの現在値と一致する |
| 1-3 | 存在しないアドレスが NG になる | デバイスの上限をまたぐ範囲を指定（例：D の上限付近） | 上限までは OK、それより先は `NG_ILLEGAL_ADDR`。`NG_COMM_ERROR` にならない |
| 1-4 | 通信が途切れても止まらない | 周期実行（`--interval 5`）中に LAN ケーブルを抜き、30 秒後に戻す | 抜いている間は `NG_COMM_ERROR`／`NG_TIMEOUT`。戻すと自動で再接続して OK に戻る |
| 1-5 | 所要時間 | フルスキャン（工場停止中のみ） | 完了まで止まらない。所要時間を記録する |

## 2. メーカー別の確認

### 三菱電機（SLMP：iQ-R / Q / FX5）

- [ ] **X/Y/B/W のアドレス**：`--device X --range 0-31 --hex-addresses` で読み、CSV の `address_hex`（X0〜X1F）が GX Works の表記と一致すること
- [ ] **1 回の読み出し量**：`--device D --range 0-899` が分割されずに読めること。読めない機種では、`NG_ILLEGAL_ADDR` が出たあと、分割して全点 OK になること
- [ ] **R（ファイルレジスタ）未設定の機種**：R のフルスキャンが数秒で `NG_ILLEGAL_ADDR` として終わること
- [ ] **4E フレームや ASCII 交信の設定**：PLC 側が 3E・バイナリ以外の設定だと接続できないので、PLC の設定を確認する

### キーエンス（KV シリーズ：SLMP / EtherNet/IP）

- [ ] SLMP で `--device D`（KV の DM に対応）の値が KV STUDIO と一致すること
- [ ] EtherNet/IP でも応答する機種は、探索で 2 行（SLMP と ETHERNET_IP）に分かれ、出力ファイルもプロトコルごとに分かれること

### オムロン（FINS：CJ / CS / CP、NJ / NX）

- [ ] FINS/UDP と FINS/TCP の両方で `--device DM --range 0-9` の値が一致すること
- [ ] **ノード番号**：PLC の FINS ノード番号が IP アドレスの末尾と異なる場合は、設定ファイルの `options.dest_node` を指定して読めること
- [ ] **1 回の読み出し量**：古い機種で 0x110B（応答が長すぎる）が返る場合でも、分割して全点 OK になること
- [ ] **NJ / NX の EtherNet/IP 変数読み出し**：Sysmac Studio で「ネットワーク公開」にした変数を `--protocol eip --tags "変数名,配列[0]{10},構造体.メンバー"` で読み、値が一致すること
- [ ] **NJ / NX の STRING・BOOL・まとめ読み**：STRING 型が文字列で、BOOL が 0/1 で読めること。変数を 20 個程度指定しても、全部が正しく読めること（まとめた要求に対応していない場合も、1 つずつ読み直して結果が出ること）
  （シミュレーターのオムロン形式〔44820 番〕では確認済み。実機では BOOL・LREAL・文字列などの型、公開していない変数が `NG_ILLEGAL_ADDR` になることも確認する）

### シーメンス（S7-1200 / 1500 / 300 / 400）

- [ ] **アドレスの単位**：本ツールの DB アドレスはワード番号（バイト位置 = 番号 × 2）。`DB1` の `DBW10` は `--device DB --range 5-5` で読めること
- [ ] **DB のサイズより先**：DB の末尾より先を含む範囲で、末尾までは OK、その先は `NG_ILLEGAL_ADDR`（再接続が起きない）こと
- [ ] **S7-1200 / 1500**：PLC 側で「PUT/GET 通信を許可」し、DB の「最適化されたブロックアクセス」をオフにしないと読めない
- [ ] S7-300 / 400 はスロット 2。`options.slot` を指定しなくても自動で試すこと
- [ ] **探索結果の機種・型式・ファームウェア**：TIA Portal の「オンラインと診断」に表示される CPU の型式（6ES7 …）・ファームウェアと一致すること（シミュレーターでは確認済み。CPU 情報を返さない設定でも、メーカーは「シーメンス」になること）

### Rockwell（Logix / SLC / MicroLogix：EtherNet/IP）

- [ ] **Logix（ControlLogix / CompactLogix）**：`--tags "タグ名,配列[0]{10}"` で、タグの値が Studio 5000 と一致すること
  （シミュレーターの Logix 形式〔44819 番〕では確認済み。実機では、タグ数の多いコントローラでタグ一覧の取得時間も記録する）
- [ ] **Logix のフルスキャン**：コントローラスコープ・プログラムスコープのタグがすべて読め、構造体（UDT）はメンバーごとの行になること
- [ ] **構造体・プログラムスコープ**：`--tags "構造体タグ,Program:プログラム名.タグ名"` の値が Studio 5000 と一致すること（シミュレーターでは確認済み）
- [ ] **SLC / MicroLogix**：`--device D`（N7）と `--device M`（B3）の 0〜255 番が読めること

### Modbus/TCP 機器（横河、富士電機、IDEC、インバーター・計器など）

- [ ] **ユニット ID**：ゲートウェイ経由の機器は `options.unit_id` を指定して読めること
- [ ] **1 回の読み出し量**：100 レジスタを読めない機器（例外 03 が返る）でも、分割して全点 OK になること
- [ ] **アドレスの数え方**：機器のマニュアルが 40001 起点などの場合、本ツールのアドレスは 0 起点（40001 → HR0）であること

## 3. 既知の制限（実機で確認できたら更新する）

- オムロン NJ / NX の EtherNet/IP 変数読み出しは、シミュレーターでのみ確認済み。読めない場合は FINS を使う
- オムロン NJ / NX はタグ一覧を取得できないため、フルスキャンでは変数を読まない。構造体の変数はメンバーを指定するか、設定ファイルの `scan.tag_members` にメンバー名を書く（どちらもない全体指定は `NG_UNSUPPORTED`）
- Logix の構造体（UDT）はメンバーごとに出力する。文字列型（STRING）は値をそのまま文字列で出力する
- プログラムスコープのタグは、`Program:プログラム名.タグ名` の形で `--tags` に指定する
